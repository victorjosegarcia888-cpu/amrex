2. CRITICAL PICOGK GEOMETRY LAWS (FAILURE TO OBEY CAUSES CRASHES)
--------------------------------------------------------------------------------
[LAW 1] WATERTIGHT 2-MANIFOLD MESHES:
   - Any `PicoGK.Mesh` converted to `PicoGK.Voxels` using `new Voxels(mesh)` MUST BE 100% CLOSED (Watertight).
   - All tubular or revolved meshes MUST include END CAPS at Z = Z_start and Z = Z_end.
   - Triangles must have consistent counter-clockwise winding order for outward normals.

[LAW 2] NO IN-LOOP VOXEL CREATION:
   - NEVER instantiate `new Voxels()` inside `for` or `while` loops to accumulate geometry via `.Add()`.
   - ALWAYS build the entire geometry within a single `PicoGK.Mesh` or `PicoGK.Lattice` object, then execute `new Voxels(...)` ONCE outside the loop.
   - Voxel creation is computationally heavy; Mesh accumulation is O(1).

[LAW 3] API CONTRACTS & METHOD NAMES:
   - Subtract method is `.Subtract(Voxels vox)`, NOT `VoxSubtract()`.
   - Add method is `.Add(Voxels vox)`, NOT `VoxAdd()`.
   - Intersect method is `.Intersect(Voxels vox)`.
   - Lattice Beams require non-zero length: `pA` and `pB` MUST NOT be identical (`pA != pB`).
   - Coordinates MUST use positive Z orientation (`Z >= 0`). Do NOT negate Z coordinates.

[LAW 4] THREE-STAGE BOOLEAN ASSEMBLY PIPELINE:
   Always structure the final assembly into three clear domains:
   1. `voxSolidShell`: Merges liner, outer shell, and manifold outer bodies.
   2. `voxFluidDomain`: Merges cooling channels, manifold inner fluid cores, and duct cores.
   3. `voxFinal`: Executes `voxSolidShell.Subtract(voxFluidDomain)`.
